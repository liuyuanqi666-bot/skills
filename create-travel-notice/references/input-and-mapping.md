# 输入与字段映射

## 必备资料

在制作前确认以下内容完整且来源一致：

- 行程文本路径
- 团号
- 产品名称
- 领队姓名
- 领队手机号码
- 出发日期和回程日期
- 机场抵达日期时间
- 出发及回程航班号、航线、起降时间
- 每日城市、交通、描述、早餐、午餐、晚餐

产品名称、领队、日期或机场抵达时间缺失时，必须先询问用户。不得沿用模板旧值。

技能默认使用 `assets/travel-notice-blank-template.doc`，无需用户重复上传模板。只有用户指定另一套版式时，才需要提供 `.doc` 或 `.docx` 模板路径。

## 可推定但必须确认的信息

- 团号中的首个六位数字可按 `YYMMDD` 推定出发日期。
- 回程日期可按出发日期加行程天数减一推定。
- 机场抵达时间默认按出发航班起飞前3小时推定。
- 推定结果必须明确展示给用户确认；用户确认前不得制作。
- 起飞前3小时跨越零点时，机场抵达日期应为前一日。

## 首页字段

只修改：

1. 产品名称
2. 机场抵达日期时间
3. 领队姓名和电话
4. 出发航班
5. 回程航班

保持不动：

- 《出行通知书》标题
- 机场抵达位置及其后文字
- 托运行李额
- 友情提示
- 紧急联系人
- 其他未获用户授权的首页内容

## 行程表

- 标题默认写为 `团号—产品名称`。
- 列标题“日期、城市、交通、行程、餐”保持模板原文。
- 日期写为 `D1`、`D2` 等。
- 城市使用文本中“第N天”后的城市行。
- 交通使用解析后的航班号、时间及当地车辆信息。
- 行程只使用“描述：”到“交通安排：”之前的内容。
- 行程描述不得润色、纠错、删减、补充或改变标点；只允许将文本换行转换为 Word 单元格内换行。
- 餐按早餐、午餐、晚餐分行写入。
- `HOTEL：`后保持空白，除非用户明确指定。
- 文本中的住宿安排不得自动写入 `HOTEL：`。
- 购物安排、娱乐安排不属于行程描述，除非用户明确要求，不得另行写入。

## 多余天数

- 只删除模板末尾未使用的行程日。
- 从第一个未使用的 `D#` 行开始，删除到“团费包含”前一行。
- 不删除最后一个已使用行程日之后原有的空白 `HOTEL：` 行。
- 不调整行高、列宽、合并方式或边框来压缩空白。
- 内置模板提供 6 个行程日槽位。
- 若资料天数超过模板槽位，停止并要求用户提供合适模板。

## 输出

- 文件名使用 `团号 出团通知书`，保留模板扩展名。
- 不覆盖原模板。
- 只交付最终 Word 文件；检查用 JSON、PDF、PNG 和副本均放在临时目录。
