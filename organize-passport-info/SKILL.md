# 护照信息整理

## 固定规则

- 将源报表作为游客信息的唯一依据，将用户确认的文字或护照照片作为领队信息依据，将 `assets/passport-template.xlsx` 作为默认且权威的输出模板。
- 即使用户没有提供模板，也必须直接使用内置模板；不要向用户重复索取模板。只有用户明确要求更新永久模板时，才更换该资源。
- 在每次执行前读取 `references/template-spec.md`。不要凭记忆重建格式。
- 不要保留模板示例人员，不要猜测或补全缺失的身份信息。领队必须具有完整且已确认的护照字段，不能只凭领队姓名生成记录。
- 将领队作为单独记录自动放在第 2 行，即表头下方第一行；游客从第 3 行开始并保持源报表顺序。
- 保持源报表中的人员顺序；只有用户明确要求时才调整。
- 始终生成新 `.xlsx` 文件，不覆盖源文件。
- 不把源报表或真实护照信息写回本技能的 `assets/`、`references/` 或 `scripts/`。

## 输入判断

1. 先执行领队资料预检；未通过时停止，不读取并生成最终表格。
2. 找到源护照或出行人报表；支持标准 `.xlsx`、传统 `.xls` 和 HTML 格式的伪 `.xls`。
3. 默认使用内置模板。只有用户明确要求更换或更新永久模板时，才使用新的模板文件。
4. 优先使用用户明确指定的输出文件名。
5. 未指定文件名时，使用 `0领队{领队姓名}.xlsx`。

## 领队资料预检

确认模板所需的领队字段全部齐全：

- 中文姓名，用于文件名和身份核对。
- 英文姓名，格式为 `SURNAME/GIVEN NAME`。
- 出生日期。
- 性别。
- 国籍。
- 护照号码。
- 护照有效期。

用户可能提供文字，也可能提供护照照片：

1. 用户提供文字时，逐字段检查；缺少任一字段时，一次性列出缺项并询问。
2. 用户提供护照照片时，目视读取资料页，并用 MRZ 交叉核对英文姓名、出生日期、性别、国籍、护照号和有效期。
3. 照片模糊、反光、裁切、遮挡、分辨率不足或字符不能唯一确定时，指出具体字段并请用户补发清晰照片或文字。
4. 图片正文与 MRZ、图片与用户文字、不同图片之间存在冲突时，列出冲突值并询问以哪个为准。
5. 不得从姓名或照片外观推断性别、国籍或其他字段。
6. 未获得完整、清晰且无冲突的领队信息前，禁止生成表格或把姓名当成完整护照记录。

全部通过后，将领队资料保存为会话工作目录中的临时 JSON，格式如下：

```json
{
  "chineseName": "张伟",
  "englishName": "ZHANG/WEI",
  "birthDate": "1980-01-01",
  "gender": "男",
  "nationality": "CHN",
  "passportNo": "E00000000",
  "passportExpiry": "2030-01-01"
}
```

该临时 JSON 只用于本次制表，不得保存进技能目录。

## 数据清洗与映射

- 识别字段语义，不仅依赖固定列号。兼容“中文姓名/中文名”“英文姓名/英文名/姓名拼音”“证件号码/护照号码/护照号”“证件有效期/护照有效期”等常见标题。
- 删除订单号、保险状态、内部备注、重复预订字段和没有身份信息的系统占位记录。
- 仅当姓名、出生日期、护照号和有效期等核心身份字段均为空时，将记录视为占位行。
- 如果记录包含部分身份信息但缺少必要字段，停止并向用户列明问题，不要静默删除。
- 将中文姓名按源报表原值写入第一列，不拼音化、不拆分、不自行更正。
- 将 `SURNAME/GIVEN NAME` 按第一个 `/` 拆为姓和名，去除两端空格并转为大写；保留内部空格和连字符。
- 将日期转换为八位 `YYYYMMDD` 数值。
- 将男转换为 `M`、女转换为 `F`。
- 按内置模板批注使用国籍代码：中国 112、印度尼西亚 125、越南 185、菲律宾 155。未知国籍必须询问，不要猜测。
- 将护照号码按文本保存并转为大写，保留可能的前导零。
- 最终列顺序固定为：中文姓名、姓、名、出生日期、性别、国籍、护照号码、护照有效期。

## 执行

优先运行 `scripts/build-passport-report.mjs`，并传入：

```text
--source <源报表绝对路径>
--template <本技能 assets/passport-template.xlsx 的绝对路径>
--leader-data <已确认领队 JSON 的绝对路径>
--output <最终文件绝对路径，可选>
```

使用当前环境可用的 Node 运行脚本。脚本依赖 `@oai/artifact-tool`：若当前环境提供该包（如 Codex 主运行时），在会话专用临时目录创建指向其 `node_modules` 的符号链接，并从该临时目录运行脚本副本，不要修改运行时目录；若不可用（如 Claude Code），跳过脚本，改用下一段的回退方式。

当源文件是真正的旧版二进制 `.xls` 时，先使用可用的 LibreOffice/soffice 无损转换为临时 `.xlsx`，再执行脚本。临时转换文件不得作为最终交付物。

如果脚本无法运行或无法识别源报表结构，使用当前环境的表格能力（Codex 的 `Spreadsheets` 技能，或 Claude 的 `xlsx` 技能/openpyxl）检查源表并完成必要的字段定位，但仍须以同一个内置模板、映射规则和验证标准生成结果。

## 格式要求

- 直接导入内置模板并填值，不要从空白工作簿重建。
- 保留可见表头、标题批注、A:H 列宽、行高、字体、边框、换行、数据类型及打印参数。
- 第 1 行保留为隐藏视觉标题行；第 2 行固定写入领队并使用模板首条数据行样式；游客从第 3 行开始并使用模板常规数据行样式。
- 人数超过模板预留行时，继续复制常规数据行的完整格式。
- 人数少于预留行时，清除剩余模板数据及多余格式，不要留下非必要的空白边框行。
- I:P 不得写入任何内容或身份信息。
- 不改变标题批注中的日期、性别和国籍代码说明。

## 二次核对

导出前逐条核对：

- 中文姓名、英文姓名拆分、人员顺序、出生日期、性别、国籍代码、护照号和有效期。
- 领队必须是第 2 行，游客必须从第 3 行开始并保持源报表顺序。
- 有效人员数、删除的占位行数、部分缺失记录和重复护照号。
- 领队和游客的护照号必须整体唯一；发现重复时停止并提示用户。

导出后必须：

1. 重新打开生成的 `.xlsx`。
2. 将 A:H 的输出值与预期矩阵逐项比较。
3. 扫描 `#REF!`、`#VALUE!`、`#DIV/0!`、`#NAME?` 和 `#N/A`。
4. 渲染最终工作表，检查列宽、行高、字体、边框、隐藏标题、批注和内容截断。
5. 验证 `.xlsx` 文件结构可以正常打开。

全部通过后再交付。最终回复分别概述领队人数、游客人数、总人数、删除的占位行数、异常情况及二次核对结果，不在聊天中展示完整护照号码。

## 输出

- 未指定文件名：`0领队{领队姓名}.xlsx`。
- 已指定文件名：遵从用户要求，并确保扩展名为 `.xlsx`。
- 除非用户要求，不交付预览图、核对日志或中间文件。
- 如果不能直接写入用户电脑桌面，提供最终文件下载入口并提示下载时选择桌面。
